# Repo audit — 2026-10-21

Routine pass over the repo: README structure and coverage table against the filesystem, `00_index/topics.md` section counts against the filesystem, every relative Markdown link in every `.md` file, and backticked path references that point at files the kit says exist.

## Findings

### UF — undocumented folder: `jnk/` (Jenkins)

`jnk/notes/0000-primer-jenkins.md` is a first-contact Jenkins primer that no index file mentioned. The folder name follows the kit's existing alias convention (`graf/`, `grafc/`, `otel/`, `plm/`, `vlt/`), and the `jnk-` task-ID prefix in the backlog maps to `jnk/` the same way `arg-` maps to `ArgoCD/` and `git-` maps to `Git/`. Left in place — moving it would break the prefix→folder mapping — and documented instead: added a `jnk/` bullet to the README Layout list, a `Jenkins (jnk/)` row to the README coverage table, a `Jenkins · 1 file` section to `00_index/topics.md`, and the primer to the Tools list in `00_index/quick-links.md`.

### DR — README tool-family count was wrong

The README's "What's in here" paragraph claimed **27 tool families**. The coverage table has 22 tool rows, and adding the undocumented `jnk/` folder makes 23 folders on disk — `GitLab` is a symlink to `GitLab CI`, not a separate family. Corrected to 23.

### CR — README coverage-table count corrections

Recounted every tool folder on disk. Three cells were wrong:

- Grafana (`graf/`): Docs 2→3 (`how-i-wired-grafana-into-prometheus-and-alertmanager-...md` was on disk but unlisted), Scripts 1→2 (`build-multi-panel-service-dashboard-via-http-api.py` was on disk but unlisted)
- Helm: Docs 5→6 (`helm-chart-testing-strategies.md` was on disk but unlisted)

All other cells in all 23 rows matched the on-disk counts exactly.

### CR — `00_index/topics.md` count drift

Section headers and per-category counts had drifted from disk in six tool sections:

- ArgoCD: 11 → 27 files (the Vault/External Secrets doc, the application helper script, the fleet ApplicationSet manifest, and the 13-file `multi-cluster-gitops-repo/` template were all unlisted)
- FluxCD: 7 → 8 files (Docs 1→2, the GitHub GitOps wiring doc was unlisted)

- Helm: 55 → 56 files (Docs 5→6)

All section totals and per-category counts now match disk for every tool section.

### BL — `Helm/docs/chart-testing-ct-lint.md` promises a root `ct.yaml` that does not exist

The guide says "A minimal `ct.yaml` in the repository root keeps the invocation stable across machines and CI runners" and then shows the file body, but no `ct.yaml` exists at the repo root. The document is not wrong about `ct` — it is wrong about the kit's own state. Filed as backlog task `hlm-034` (add the root `ct.yaml` the guide already specifies) rather than editing the guide, because the guide's content is correct and the file is the missing artefact.

### BL — `Git/templates/git-repository-skeleton/README.md` points at a dead `runtime.txt`

Line 20 of the repository-skeleton README says "A supported runtime (see `runtime.txt` or `package.json` for specifics)", but the scaffold ships no `runtime.txt` — it is a Node/`package.json` scaffold. The pointer is dead on arrival. Filed as backlog task `git-038` to drop the `runtime.txt` mention (or ship the file) rather than patched inline, because the template is copied verbatim into user repositories and the fix has to land as a template change.

### SR — stale level-gating snapshot in the agent manifest

`/work/manifest.json` (→ `DevOps_Automation/Agent/MANIFEST.json`) is a generated index, and its `levels` block still mirrored the pre-reconciliation level state: `tool_levels` carried 30 keys (the eight concept rows were still mixed in) and the tool rows still held the corrupted values the 2026-10-21 level reconciliation recorded as resolved — e.g. Ansible `unlocked: false / L2 / next_action —` instead of `unlocked: true / L5 / L6`, Kubernetes and Jenkins `—` for every level field. An agent gating on that snapshot would have read Ansible's next allowed action as `—` and stalled the cycle.

Regenerated with the pipeline's own tool (`tools/generate_manifest.py`), which rebuilds the block from `LEVEL_STATE.md`: `tool_levels` now holds 23 tool rows, `concept_levels` holds the 8 concepts with no concept rows left in `tool_levels`, and every row matches the reconciled level table. The regenerated manifest also picks up the two backlog tasks filed below (`hlm-034`, `git-038`), taking the backlog queue from 329 to 331. The `tools` and `concepts` inventories were unchanged by the regeneration — the earlier apparent drift there was a difference in counting convention (the manifest counts top-level files per category, not recursive), not a real mismatch.
